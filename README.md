# TAM Black Friday 2026: Hire Your AI Agent in 3 Days, Live

Funnel for Truly Authentic Marketing, built on the AI Studio app scaffold
(TanStack Start + Vite + React, published by AI Studio as a full-stack app).

## Pages

| Route | Route file | Markup | Job |
|---|---|---|---|
| `/` and `/install` | `src/routes/index.tsx`, `install.tsx` | `src/funnel/pages/index.html` | Sales page. All 11 order buttons go to `/checkout` |
| `/checkout` | `src/routes/checkout.tsx` | `pages/checkout.html` | On-page $97 order form, single product (`src/funnel/CheckoutForm.tsx`) |
| `/growth-accelerator` | `src/routes/growth-accelerator.tsx` | `pages/growth-accelerator.html` | One-click $997 upsell, 6 x $197 plan popup on "No" (`src/funnel/UpsellOffer.tsx`) |
| `/foundation` | `src/routes/foundation.tsx` | `pages/foundation.html` | AI Growth Foundation application, then the booking calendar |
| `/thank-you` | `src/routes/thank-you.tsx` | `pages/thank-you.html` | Booking calendar, Zoom + calendar (.ics) details, teammate form, Product Champ login |

## How it is put together

- **Design and copy are the approved static pages, unchanged.** Each page's body markup lives in
  `src/funnel/pages/*.html` and is server-rendered as is by `src/funnel/FunnelPage.tsx`.
  Edit copy there.
- **Styles, fonts, images, the .ics file** are in `public/static/` (served at `/static/...`).
  The stylesheet is `public/static/css/styles.css`. Tailwind (`src/styles.css`) is part of the
  scaffold but is deliberately not loaded: its reset would change the design.
- **Page behaviour** (reveal on scroll, popups, share link): `src/funnel/funnel.ts`.
- **Payments** use the AI Studio Payments blocks in `src/integrations/payments/` (auto-generated,
  do not edit). The checkout and upsell are embedded on the funnel pages. No external checkout page.
- **Forms** (application, teammate) post to the CRM through `src/funnel/tracking.ts`.
  **Calendar** availability and booking: `src/funnel/calendar.ts`.

## Products and price IDs

Create these three products in AI Studio: More -> Payments.

| Product | Price | Used on |
|---|---|---|
| Hire Your AI Agent in 3 Days, Live | $97 one time | `/checkout` |
| 2027 Growth Accelerator | $997 one time | `/growth-accelerator` |
| 2027 Growth Accelerator, payment plan | $197 a month, 6 payments | `/growth-accelerator` popup |

The funnel finds them three ways, first match wins (`src/funnel/config.ts`, `src/funnel/products.ts`):

1. Env vars: `VITE_BF_MAIN_PRODUCT_ID`, `VITE_BF_MAIN_PRICE_ID`, `VITE_BF_UPSELL_PRODUCT_ID`,
   `VITE_BF_UPSELL_PRICE_ID`, `VITE_BF_PLAN_PRODUCT_ID`, `VITE_BF_PLAN_PRICE_ID`.
2. The `IDS` object at the top of `src/funnel/config.ts`.
3. Automatically, by price, from this project's Payments catalog: exactly one $97 one-time price,
   one $997 one-time and one $197 recurring. If two products share one of those
   prices, set the IDs explicitly.

Until the $97 product exists, `/checkout` shows a "Setup needed" note instead of the order form.

`.env` holds the Payments script URL, catalog API URL and project ID. It is generated by
AI Studio Payments. Do not hand edit those three lines.

## Static preview on Cloudflare Pages

The review copy at https://tam-bf-2026-preview.pages.dev is a static build of these same pages,
published to the Cloudflare Pages project `tam-bf-2026-preview` (production branch `preview`).
It is separate from the AI Studio app and never takes a payment.

Build it:

```sh
npm install
node scripts/build-static-preview.mjs
```

That script builds the app with `VITE_BF_PREVIEW=1`, asks the built server for each route
(`/`, `/install`, `/checkout`, `/growth-accelerator`, `/foundation`, `/thank-you`) and saves the
HTML to `pages-preview/site/` next to the hashed bundles in `assets/`. The pages hydrate from
those bundles, so nothing loads a `/src/*.ts` path. It also writes noindex headers and a
`Disallow: /` robots file.

`VITE_BF_PREVIEW=1` (see `src/funnel/preview.ts`) is what keeps the preview safe:

- `/checkout` shows the order summary and a note. The payment form is never loaded.
- `/growth-accelerator` shows its Yes and No buttons. Yes shows a note, No opens the payment plan
  popup, and the popup's No goes to `/foundation`. Nothing is charged.
- The application and teammate forms say they are not connected, and nothing is sent to the CRM.
- Every footer gets the line "Preview build. No payment, form or tracking is connected."

Without that variable, as in the AI Studio build, none of this applies and the pages sell for real.

Deploy it (run from `pages-preview/`, which holds the Pages config and the video function):

```sh
cd pages-preview
npx wrangler pages deployment list --project-name tam-bf-2026-preview   # note the current ID first, for rollback
npx wrangler pages deploy site --project-name tam-bf-2026-preview --branch preview --commit-dirty=true
```

If Wrangler reports error 9109, a stale `CLOUDFLARE_API_TOKEN` is set: put
`env -u CLOUDFLARE_API_TOKEN` in front of the command. Do not run `wrangler login`.

To roll back, open the project in the Cloudflare dashboard, pick the earlier deployment and
choose "Rollback to this deployment".

## Videos

The sales page, the upsell and the thank-you page each have a video slot (`data-vsl`). The page
markup names each file as `/v/<file>`; `src/funnel/media.ts` (`VIDEO_URLS`) maps the three mp4 files
and three posters to their public URLs in the Product Champ Media Library (folder "Black Friday 2026
VSL", `files.leadconnectorhq.com`), so every host plays the same files. The media library rejects
`.vtt`, so the caption tracks (burned into the video, kept for assistive tech) load from the
Cloudflare function below, which sends CORS headers. The slot is hidden only if the file answers
404; any other load error shows the player's error panel with a retry button.

Layout (VSL pattern): the video sits at the top of the hero on every page, right under the headline and
sub line, with the page's button directly under it (sales: checkout, upsell page: `#upsell-mount`, thank-you:
`#booker`). It autoplays muted behind a "Click to watch with sound" overlay; a click turns the sound on from
0:00. With `prefers-reduced-motion`, or if the browser blocks autoplay, the poster and play button show instead.
When the player scrolls out of view while playing, the same player element floats as a mini player in the
bottom corner (CSS `position: fixed`, no DOM move, so playback never restarts); the slot keeps its 16:9 box as
a placeholder. Mini buttons: play/pause, sound, expand (scrolls back to the top), close (pauses; it returns
when the visitor scrolls back up). All of it lives in `src/funnel/player.ts` and the `.bfp*` / `.hero--vsl`
rules in `public/static/css/styles.css`.

| Page | Video | Poster | Captions |
|---|---|---|---|
| `/` and `/install` | `bf-vsl-flow-v2_web.mp4` (from R2 via `/v/`; not in `VIDEO_URLS`) | `bf-vsl-flow-v2_poster.jpg` | `bf-vsl-flow-v2_captions.vtt` |
| `/growth-accelerator` | `ga27-flow_web.mp4` | `ga27-flow_poster.jpg` | `ga27-flow_captions.vtt` |
| `/thank-you` | `bfwelcome-flow_web.mp4` | `bfwelcome-flow_poster.jpg` | `bfwelcome-flow_captions.vtt` |

Fallback copy (and the VTT files): the private R2 bucket `tam-bf-2026-video`. It has no public URL. The Pages
Function `pages-preview/functions/v/[file].js` serves them at `/v/<file>` through the `VIDEO`
binding in `pages-preview/wrangler.jsonc`, with HTTP Range support so the player can seek.

Upload a video (no deploy needed, the slot appears on the next page load). Send the poster and
captions first so the player is complete the moment the video lands:

```sh
npx wrangler r2 object put tam-bf-2026-video/bf-vsl_poster.jpg --file ./bf-vsl_poster.jpg --content-type image/jpeg --remote
npx wrangler r2 object put tam-bf-2026-video/bf-vsl_captions.vtt --file ./bf-vsl_captions.vtt --content-type text/vtt --remote
npx wrangler r2 object put tam-bf-2026-video/bf-vsl_web.mp4 --file ./bf-vsl_web.mp4 --content-type video/mp4 --remote
```

Export the MP4 as H.264 video with AAC audio and "fast start" on, so it plays before it has
fully downloaded. Wrangler uploads files up to about 300 MB this way. To take a video down,
delete the MP4: `npx wrangler r2 object delete tam-bf-2026-video/bf-vsl_web.mp4 --remote`.

How a slot decides: the page asks `/v/<file>?probe=1`, which always answers 200 with
`{"exists": true}` or `{"exists": false}`. Only on `true` is the player added to the page. If the
video later fails to play, the slot hides again. The code is `initVsl` in `src/funnel/funnel.ts`.

The `/v/` route exists only on the Cloudflare Pages preview. On AI Studio hosting the slots
simply stay hidden until the same route is added there.
